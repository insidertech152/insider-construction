# السياق الثابت للـ agent — قرارات النظام

**الاستخدام:** الـ agent يقرأ الملف ده قبل أي تنفيذ، ولا يغيّر أي قرار فيه من دماغه. قسم «قرارات مفتوحة» مش ملزم، ولازم تسأل صاحب المشروع لما توصله.

## 1. المنتج

نظام إدارة لشركات التشطيب والديكور في السوق المصري. الهدف أن يدير المشاريع والشركة نفسها، ويعرّف صاحب الشركة **ربحية كل مشروع والشركة كلها، وأنهي مكان بتخسر فيه**. واجهة عربية RTL أولاً مع نسخة إنجليزية لاحقاً، وتطبيق موبايل (PWA) لمهندس الموقع.

## 2. القاموس

| الكيان | التعريف |
|---|---|
| الطرف | سجل واحد لأي شخص أو شركة، وله أدوار: عميل، مورد، مقاول، مطوّر. الطرف الواحد ممكن يبقى أكتر من دور |
| الفرصة | عميل محتمل لسه ما اتعاقدش |
| المعاينة | زيارة ومقاسات وصور |
| بند الكتالوج | اسم + وحدة + سعر + تكلفة تقديرية + نوع عمل (قائمة أسعار الشركة) |
| عرض السعر | نسخ، بنود وكميات، صلاحية وتاريخ انتهاء |
| العقد | اتفاق ملزم بنسخة مجمدة من عرض السعر. نوعه: عميل نهائي أو مقاول باطن لمطوّر. فيه جدول دفعات وملاحق |
| المشروع | يتولد من عقد موقّع، وله ميزانية معتمدة وفريق |
| بند المشروع | بند من العقد بيتنفذ، عليه الإنجاز والتكلفة |
| أمر التغيير | تعديل على البنود أو القيمة بعد العقد |
| التكلفة | أي مصروف على مشروع أو عام: شراء، عمالة، مقاول، مصروف، راتب موزع |
| المستخلص | مطالبة مالية على نسبة إنجاز، نوعان: صادر للعميل ووارد من مقاول |
| الدفعة | تحصيل أو سداد: نقدي أو شيك أو تحويل |

**السلسلة:** فرصة ← معاينة ← عرض سعر ← عقد ← مشروع ← بنود ← (إنجاز + تكاليف + أوامر تغيير) ← مستخلصات ← تحصيل.

**معادلة الربح:** قيمة العقد + أوامر التغيير المعتمدة − التكاليف الفعلية.

## 3. الأدوار (مسودة)

صاحب الشركة / المدير العام، مدير المشاريع، مهندس الموقع (موبايل فقط)، المكتب الفني / التقدير، المبيعات، المشتريات، أمين المخزن، المحاسب / المدير المالي، المصمم، الموارد البشرية، مدير النظام، العميل (خارجي)، المقاول/المورد (خارجي، لاحقاً). المستخدم الواحد ممكن يحمل أكتر من دور. السايد بار يعرض لكل مستخدم أقسامه فقط.

## 4. القرارات المعتمدة

### 4.1 البنود
- البند نسخة **مجمدة في كل مرحلة**: كتالوج ← عرض سعر ← عقد ← مشروع، مع رابط للأصل.
- بند العقد هو **الأساس الدائم** للمقارنة (المقدّر مقابل الفعلي). أوامر التغيير تعدّل بند المشروع من غير ما تمس الأساس.

### 4.2 المشروع والعقد
- المشروع لا يتولد إلا من **عقد موقّع**، بدون استثناء.
- المشاريع الصغيرة: قبول عرض السعر يولّد **عقداً مبسطاً** بضغطة واحدة (نفس البنود المجمدة وجدول دفعات افتراضي). المشاريع الكبيرة تستخدم العقد الكامل.
- العقد الأصلي يفضل مجمداً، وقيمة العقد المعدلة = الأصلية + أوامر التغيير المعتمدة.

### 4.3 الكتالوج
- اختياري: كل شركة جديدة تبدأ بكتالوج فاضي. البند الحر مسموح دائماً في عرض السعر.
- **نوع العمل إجباري** على كل بند، والتكلفة اختيارية (بند بلا تكلفة يتعلّم «هامش غير معروف»).
- زر «احفظ في الكتالوج» على البند الحر، استيراد الكتالوج من Excel، وقائمة أنواع أعمال جاهزة (دهانات، كهرباء، سباكة، بلاط، نجارة، جبس بورد...).

### 4.4 ميزانية التكلفة الداخلية
- البند في الكتالوج له **تكلفة تقديرية للوحدة** (مع تاريخ آخر تحديث وتنبيه لو قديمة)، وتتنسخ مع السعر في عرض السعر.
- عند إنشاء المشروع تتجمع التكاليف تلقائياً **حسب نوع العمل** كميزانية تكلفة. مدير المشروع يعدّلها قبل الاعتماد، وبعد اعتماد الإدارة **تتجمد**. الصرف الفعلي يتسجل على نوع العمل.
- التكلفة والهامش تظهر **بصلاحية فقط**: لا تظهر للمبيعات ولا للعميل ولا في نسخة العميل المطبوعة.

### 4.5 الإنجاز
- يتقاس **لكل بند**، بقياسين منفصلين: إنجاز بنود العقد (الإيراد المكتسب ومستخلص العميل)، وإنجاز بنود المقاول (التكلفة المستحقة ومستخلص المقاول). يرتبطان بنوع العمل.
- مهندس الموقع يدخل النسبة ومدير المشروع يعتمدها. الإنجاز غير المعتمد **لا يدخل** في إيراد ولا تكلفة ولا مستخلص.

### 4.6 المقاولون
- التكلفة المستحقة (تمشي مع الإنجاز المعتمد وتدخل في الربحية) **منفصلة** عن النقدية المصروفة (تدخل في التدفق النقدي وفي رقم «فلوس برا عند مقاولين»).
- الفرق بينهما سلفة (أصل) تتخصم من المستخلصات القادمة.
- السلفة مسموحة بأي نسبة حتى 100%، لكن فوق **حد تحدده الشركة** يحتاج الدفع موافقة المدير العام. تنبيه أحمر لما المدفوع يعدّي الشغل المعتمد بفارق كبير. محتجز ضمان اختياري.
- نوعا عقد المقاول: عمالة فقط، أو توريد وتركيب.

### 4.7 دفعات العميل
- يختار كل عقد نوعاً: **دفعات بمراحل** (نسبة ثابتة لكل دفعة) أو **مستخلصات دورية** بنسبة الإنجاز. العقد المبسط يتولد افتراضياً بدفعات بمراحل قابلة للتعديل.
- شروط الاستحقاق: عند التوقيع، عند اكتمال نوع عمل أو نسبة منه، عند وصول إنجاز العقد لنسبة، تاريخ ثابت، عند التسليم.
- الدفعة تستحق **بإنجاز معتمد فقط**. النظام **ينبّه ولا يحصّل ولا يوقف الشغل تلقائياً**. لمدير المشروع زر «إيقاف مؤقت بسبب التحصيل» يسجل السبب والتاريخ.

### 4.8 تكلفة الخامات
- تتسجل عند **الاستلام في الموقع** (شراء مباشر لمشروع) أو عند **الصرف من المخزن لمشروع**، لا عند الفاتورة ولا الدفع. مرتجع الموقع يقلل التكلفة.
- أي أمر شراء أو صرف أو مصروف نقدي يحمل إجبارياً: **مشروع (أو «عام») + نوع عمل**.

### 4.9 الربحية والرواتب
- **هامش المشروع (قبل المصروفات العامة)** هو الرقم الأساسي. توزيع المصروفات العامة على المشاريع **اختياري** (الشركة تختار الطريقة). ربحية الشركة = مجموع هوامش المشاريع − المصروفات العامة.
- الموظف اللي بينزل المواقع: **نسبة تخصيص شهرية يدوية** يحددها مدير المشاريع على المشاريع (نوع عمل «إشراف»). بدون تخصيص يكون راتبه مصروفاً عاماً تلقائياً (مثل المحاسب والمبيعات والإدارة).
- أنواع الأجر: راتب شهري ثابت، يومية (تكلفة مباشرة على المشروع)، بالمشروع.
- لاحقاً: حساب نسبة التخصيص من أيام الحضور الفعلية بالموقع.

### 4.10 أوامر التغيير
- الدورة: طلب ← تسعير (بيع + تكلفة) ← موافقة العميل ← اعتماد داخلي ← تنفيذ.
- **تغيير عاجل** يفتحه مهندس الموقع من الموبايل (وصف + صورة + نوع عمل). مدير المشروع يعتمد التنفيذ، وحالته «منفّذ بدون موافقة عميل». تكلفته تتحسب فوراً، ولا يدخل إيراداً أو مستخلصاً إلا بموافقة العميل. لوحة صاحب الشركة تعرض إجمالي «التكلفة المعرضة» مع تنبيه بعد مدة يحددها المستخدم.

### 4.11 إعدادات عامة
- أرقام إنجليزية (0-9) افتراضياً، مع إعداد على مستوى الشركة للهندية.
- الخط: Almarai للعربي، Inter للإنجليزي.

## 5. الأدوات وقواعد الكود

- Next.js (React) + TypeScript + Tailwind CSS + shadcn/ui + TanStack Table + React Hook Form + Zod + Recharts + Phosphor Icons + Framer Motion + PWA.
- كل قواعد الشكل في مستند «قواعد التصميم». ممنوع left وright وml وmr وpl وpr (نستخدم start وend وms وme وps وpe). ممنوع مكوّن خاص بقسم: أي مكوّن جديد يتضاف للديزاين سيستم.
- كل صفحة تعالج أربع حالات: تحميل (Skeleton)، فاضية، خطأ، لا توجد صلاحية.
- ممنوع نسخ أي كود أو رسومات من مرجع Admindek.
- كل قسم يتناقش بقالب ثابت: الهدف والمستخدمون، الشاشات، الحقول، الأزرار، الكروت، دورة الحياة، الربط، الصلاحيات والاعتمادات، الإشعارات، الحالات الاستثنائية، تجربة الموبايل.

## 6. مقترحات لم تُعتمد بعد (تُناقش قبل التنفيذ)

- تخزين المبالغ كأعداد صحيحة (بالقرش) لا كأرقام عشرية.
- إخفاء التكلفة والهامش يتم في الخادم (الـ API) وليس في الواجهة فقط.
- سجل تدقيق للاعتمادات والتعديلات المالية، وحذف منطقي بدل الحذف النهائي.
- نقطة تعادل شهرية للشركة في لوحة صاحب الشركة.

## 7. قرارات مفتوحة (اسأل قبل البناء)

- نموذج البيع: اشتراك مستضاف، أم نسخة لكل شركة، أم استخدام داخلي أولاً؟ (يحدد عزل بيانات الشركات).
- قاعدة البيانات (الترجيح: PostgreSQL).
- النوافذ المنبثقة والسايد بار المطوي ونسخة الموبايل.
- الأقسام التي تدخل الإصدار الأول.
- الفاتورة الإلكترونية (مصلحة الضرائب): تُصمَّم حقول الفواتير لتناسبها من البداية، والربط الفعلي لاحقاً.
